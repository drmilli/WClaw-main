What’s Inside

Built for edge, not luck

Every component is designed around one idea: ensemble weather models know more than the retail market does.

🌧
Multi-Model Consensus
Combines GFS (31 members, weight 1.0) and ECMWF (51 members, weight 1.2) into a weighted probability. Four confidence tiers: LOCK, STRONG, SAFE, NEAR-SAFE.
📈
Kelly Criterion Sizing
Quarter-Kelly position sizing with per-confidence multipliers. LOCK bets 1.5×, STRONG 1.2×, SAFE 1.0×. Max position capped at 5% of bankroll.
🔍
Real-time Discovery
Discovers markets via Polymarket Gamma API event slugs. Scans 6 cities × 7 forecast days every cycle. The Gamma tag param is broken — slugs are the workaround.
⚡
Circuit Breaker
Halts trading automatically after 3 consecutive losses. Risk state is reconstructed from SQLite on startup — durable across process restarts and cron cycles.
📄
Paper & Live Modes
Paper mode logs virtual trades instantly with no external calls. Live mode places GTC limit orders via the Polymarket CLOB API with EIP-712 signing. Switch with MODE=live.
✅
Auto Settlement
Fetches observed temperatures from Iowa State Mesonet CLI. Matches actual highs/lows against position brackets and updates P&L automatically. 12–24hr data lag is expected.
The Process

How WeatherClaw works

Three steps from weather model to Polymarket position.

Step 01
Fetch Ensembles
GFS (31 members) and ECMWF (51 members) provide full probability distributions over daily high and low temperatures for 7 days ahead. Cities are fetched sequentially with 200ms delays to respect the 10K/day rate limit. All temps converted to Fahrenheit internally.
Step 02
Find the Edge
Polymarket market titles like “be between 40–41°F” are parsed into bracket ranges. Model probability is compared to market price. Edge = modelProb − marketPrice. Signals require ≥8% edge and at least 2 hours to settlement.
Step 03
Execute & Settle
Kelly-sized positions are placed as paper trades or live CLOB limit orders. Iowa State Mesonet data settles outcomes the following day. Wins, losses, and running P&L are tracked in SQLite with WAL mode for concurrent read access.

Questions

Frequently asked

How accurate are GFS and ECMWF ensemble models?
GFS and ECMWF ensemble models achieve 85–90% accuracy on 1–3 day temperature forecasts. The ensemble spread (31 members for GFS, 51 for ECMWF) gives a full probability distribution rather than a point forecast. Polymarket retail pricing often reflects uniform 1/N priors, creating systematic mispricings that WeatherClaw exploits.
What’s the minimum bankroll required?
The default BANKROLL_USDC=50 is a practical minimum. With quarter-Kelly sizing and a 5% max position cap, individual trades range from $1–$3 USDC. For live mode you’ll also need a small amount of MATIC on Polygon for gas fees (a few cents per transaction).
How is position size calculated?
WeatherClaw uses the Kelly criterion: f* = (b·p − q) / b where b is the net odds, p is the model probability, and q = 1−p. The raw Kelly fraction is multiplied by 0.25 (quarter-Kelly) and a confidence multiplier (1.0–1.5× based on LOCK/STRONG/SAFE), then capped at MAX_POSITION_PCT of bankroll.
What happens when the circuit breaker triggers?
After 3 consecutive settling losses, all new trade execution is automatically paused. The breaker resets on the next winning settlement. Risk state is reconstructed from SQLite on every process start, so the breaker survives restarts and one-shot bun run scan cycles.
Can I paper trade before using real money?
Yes — MODE=paper is the default. Paper trades are logged instantly to SQLite with identical data to live trades. Settlement, P&L tracking, and the circuit breaker all work identically. Run bun run paper for the continuous dev loop, or bun run scan for a one-shot cycle.
How does automatic settlement work?
The bun run settle command fetches actual observed temperatures from the Iowa State Mesonet CLI API. It checks each open position whose market date has passed, compares the observed high/low against the bracket boundaries, and marks positions as won or lost. Iowa State data typically lags 12–24 hours after the day ends — this is expected and the settle command handles it gracefully.
